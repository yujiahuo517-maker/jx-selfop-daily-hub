# 01 超级补贴自动提报

- task_id：`super_subsidy`
- 优先级：P0
- 执行人：张三（ERP `zhangsan1`）
- 排期：每天 18:50
- 依赖：`blacklight`；优先使用 `$blacklight-daily-super-subsidy`，未安装时用 bybt 配置与报名工具按本文执行

## 固定参数

| 参数 | 值 |
|---|---|
| **资源位 ID（resourceId）** | **2935**（超级补贴） |
| **收品池 areaId** | **319901**（接口里传这个，不是 2935） |
| **活动编号 activityId** | **101664799**（`bybt.forms` 的 key；活动切换以配置为准） |
| 场域 | **京喜自营**（`applySkuType=3`） |
| 网关 | `bid-activity.jd.com`（yx bybt 场域） |

资源位 ID 固定 2935（resourceId），不要每次重新确认；**调接口时的 areaId 是 319901**，把 2935 当 areaId 会返回「开放收品池未发布」或「获取时间信息失败」。活动编号仍从 bybt 配置读取，**禁止猜活动号**。

> 2026-11-20 本机实跑实证：`apply_dryrun/apply` 用 `area_id=319901, activity_id=101664799, resource_id=2935, bid_num=10000`；回读用 `POST /apply/bid/applied/page` 且 **`activityProgressStatus=0`**（新报名在这一档，`=2` 只返回已生效的历史记录，会误判为 0 条）。

## 前置检查

1. 确认当前登录 ERP 是 `zhangsan1`；不是本人则停止。
2. 从 Blacklight 的 bybt 配置读取活动编号和入口，**不要猜活动号**。
3. 确认定价底料、平台试算接口、报名管理接口可用；任一缺失，对应 SKU 进人工复核。
4. 确认今天没有已执行成功的幂等记录；若已完整执行，直接汇报，不重复报名。

## 执行步骤

1. 拉取本人名下可报名候选与已报名管理列表。
2. 用「采销可控价」计算毛利率：

   ```
   毛利率 =（平台试算客户到手价 − 采销可控价）÷ 平台试算客户到手价
   ```

   采销可控价必须包含采购、物流、CPS、京喜广告成本，是**全成本口径**。

3. 按规则过滤：普通品 ≥5%；有广告成本/广告智能优惠券/京准通券/其他广告叠加 ≥20%，低于 20% 直接剔除。
4. 对每个 SKU 先运行 `apply_dryrun`，取得 `confirm_token`；预检失败不提交。
5. 串行提交，库存固定 10000，报名价用平台真试算的 `max_margin` 建议价。
6. 全部结束后回读 `applied_sku_ids`，用报名集合前后差确认真实新增；不得只看提交回执。
7. 按通知规则输出结果。

## 18 条硬规则

1. 只处理 ERP `zhangsan1` 本人名下 SKU，不操作其他采销商品。
2. 活动编号和入口从 bybt 配置读取，不自行猜测。
3. 普通商品超级补贴后毛利率 ≥5%。
4. 有广告叠加的商品超级补贴后毛利率 ≥20%，低于 20% 直接剔除。
5. 毛利率按「（平台试算客户到手价 − 采销可控价）÷ 平台试算客户到手价」。
6. 采销可控价采用采购、物流、CPS、京喜广告成本在内的全成本口径。
7. 命中 `rejectLabelId=238`，或驳回原因为「不支持随机款报名，请报单一颜色/规格」「不支持随机款报名，请报单一规格」的 SKU，永久剔除。
8. 平台出资券、券促叠加口径不确定、定价底料缺失、试算异常的商品只进人工复核。
9. 已生效、审核中、竞价中或其他占坑 SKU 不得重复报名。
10. 报名库存固定 10000。
11. 报名价使用平台真试算建议价，采用 `max_margin` 方案。
12. 每个 SKU 必须先 `apply_dryrun`，通过预检并取得 `confirm_token`。
13. 所有报名串行执行，禁止并发提交。
14. 完成后回读 `applied_sku_ids`，以前后差确认结果。
15. 单次候选超过 200 个时停止执行并通知，不得自行拆批绕过。
16. 不自动修改标题、京东价、券促、上下架状态，不自动退出活动。
17. 红盾敏感词、标题不合规、登录失效、活动配置缺失、接口异常、预检失败、回读未报上时，立即停止该 SKU 并反馈原始原因。
18. 登录失效时不要启动 Chrome；通知使用 Edge 手动完成 ERP 登录和验证码。

## 通知规则

- 没有新增候选、没有报名、没有异常：保持安静。
- 有成功报名：候选数、预检通过数、回读确认新增数、SKU 与报名价。
- 有异常：SKU、失败阶段、平台原始原因、是否需要人工处理。
- 单独汇报：广告毛利低于 20% 剔除数、随机款剔除数、人工复核数、未报上 SKU。
- 不要生成 Excel；直接在任务结果中简洁呈现。
