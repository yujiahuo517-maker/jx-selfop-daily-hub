# 07 SPU 每日骤降 + 机会看板

- task_id：`spu_daily_drop_board`
- 优先级：P0
- 执行人：7 位采销全员（PDF 未指定负责人）
- 排期：每天 09:30
- 依赖：`blacklight`、本地 Node（webapp）

## 一、取数口径（先验证再建看板）

1. 用 Blacklight 技能包解释器和 `BlacklightClient(no_telemetry=True)`。
2. EasyBI：

   ```
   dataset_id = 1025136
   dept = <本人二级部门编号>
   dept_level = 2
   filters = [{field: cate_op_erp, op: in, values: ["<本人ERP>"]}]
   dims = [dt, spu_id]
   metrics = [京喜成交订单销量_成交, 京喜成交订单金额_成交, 京喜商详浏览UV]
   ```

3. `page_size` 上限 1000，单日可能几千行；必须按 `cate_1 → cate_2 → cate_3` 逐级切分补全，并核对「切分后行数合计」与「不分页总数」一致；不一致如实说明。
4. 主口径用 T+1 离线结算数据（昨日 vs 前日）。实时源 `index.realtime_multi` 若返回结构变化就不用，并在日报注明。
5. 落地：
   - `data/spu_daily_<日期>.json` 存明细；
   - `data/dashboard_history.json` 存最近 14 天（同日覆盖），方便断点续跑。

## 二、骤降判定

1. 昨日 vs 前日，销量 / GMV / 商详 UV 任一项降幅 > 30%。
2. 必须有基数：前日 GMV ≥300 或 销量 ≥10 或 UV ≥50，否则不算。
3. 损失 GMV = 前日 GMV − 昨日 GMV，按损失倒序。
4. 原因只能落在 8 类，不得自创：

   `流量骤降 / 转化下降 / 券促到期 / 下架断供 / 商品归属变更 / 大促回落 / 小基数波动 / 待观察`

   判定必须带证据，例如「主力 SKU xxx 在售=否」「UV -43%，低于周均」「券 0 张」。

5. 特别处理：某 SPU 昨天还在卖、今天整个从本人类目口径消失，但查它的 SKU 仍「在售=是」且当天仍有成交 → 属于「商品归属变更」，不能算本人掉量，单独归类。
6. 判定为「流量骤降 / 券促到期 / 下架断供 / 商品归属变更」的，逐个回查：
   - EasyBI 查 `jdr_jx_sku_on_sale_flag`，比两日在售状态；
   - `osw_pricing_query` 查主力 SKU（前日 GMV 最大）的到手价、券、促销。
   - 接口失败或字段缺失就写「未取到」，不许编。

## 三、对话日报（四块，直接 Markdown 表格）

1. **总览**：昨日 销量/GMV/UV + 环比 + 占大促前周均；一句话结论。
2. **骤降红榜**：按损失 GMV 取前 12，列 SPU、商品、销量/GMV/UV 前→当、损失、判定。
3. **重点新生力**：前 7 日零销量 + 最近连续两日出单的 SPU，按客单价排序，≥100 元标 ★高客单。
4. **今日行动**：3～5 条，按优先级，写清哪个 SPU、做什么动作、数字依据。

第一行必须是：`📊 看板已更新（YYYY-MM-DD）`。不要生成 md 文件。

## 四、在线看板

1. 目录 `webapp/`，零依赖 Node（不要 `npm install`），监听 `0.0.0.0:8080`，数据和页面同一服务。
2. 页面：
   - 顶部 stats（GMV/销量/UV/周均/命中数/机会数）+ GMV 趋势折线（14 天）；
   - 骤降明细用紧凑表格，列：`# / 商品 / 销量前→当 / GMV前→当 / UV前→当 / 损失GMV / 原因 / 状态 / 备注`；
   - 原因 TAB 按计数显示（全部、待处理、各原因）；
   - 底部机会榜表格 + 类型 TAB（冲量爆发/连续放量/高客单/回弹中/待转化/新开单）；
   - 每行可改判定/处理状态/备注，前端 PATCH 到后端落盘 `store.json`；第二天同步新数据不能覆盖人工填写；
   - 支持 CSV 导出；只看本人，不要操作人输入框和共享功能。
3. 可靠性：
   - 计划任务开机自启；另一个任务每 5 分钟健康检查，挂了自动拉起；
   - 关掉「电池供电不启动」等限制；不要用会被策略拦的 cmd 包装，直接拉起 node；
   - 未知路径回落首页，不出现 404；
   - 桌面 `.url` 快捷方式指向 `http://127.0.0.1:8080/`。
4. 每日更新流程：拉当日明细 → 写 `day.json` → 写历史 → 生成机会榜 → 同步进 `store.json`（热加载，不重启）。

## 五、每天自动提醒

建每天 09:30 的定时任务：按口径跑完、更新网页看板、在对话输出四块日报、最后给网页地址和「待处理 N 个骤降 / M 个机会」。

## 六、登录态

取数报「接口返回非 JSON / 被登录页挡了」= cookie 过期：自动拉起 Blacklight 登录浏览器，点「内网用户 ERP 登录」走内网 SSO，成功后再重试；不要直接失败。
