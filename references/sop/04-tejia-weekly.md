# 04 特价提报与后续券池评估

- task_id：`tejia_weekly`
- 优先级：P0
- 执行人：全员（各自用本人 ERP，只处理本人名下 SKU）
- 排期：每天 11:30（审核窗口 11:00-15:00）；提交前必须采销本人确认清单
- 依赖：`blacklight`（yx / ms 表格报名）

## 一、报名范围与门槛

1. 前置池：「特价-前置」`area=38801203`、`activity=101766465`，用 `plan_baoyou_enroll` 产候选。
2. **必须先按本人商品档交叉过滤**：用 OSW 商品列表把非本人名下 SKU 全部剔除。规划器给的池子约 8 成是别人的品，绝不能直接报。
3. 对入池 SKU 逐个校验毛利：

   ```
   【建议价 − 2.5 − 成本 − 快递费】≥ 0   # 参与 5.9-5，我们 50% 承担时不亏
   【建议价 − 2 − 成本 − 快递费】≥ 0     # 参与 4.9-4，我们 50% 承担时不亏
   ```

   - 成本 = 采购价；
   - 快递费 = 单均物流（一般 2 元/单）；
   - 数据从商品成本接口取。
4. 报名价 = 建议价（不超额、不降价报入）。

## 二、剔除规则

- 外投品：`SKU 10190916340867`（及其它点名外投清单）一律剔。
- 东东农场：商品名含「东东农场」一律剔，除非前台价 == 建议价。
- 平台禁令清单走工具内置一套，不改。

## 三、执行与收口

1. 提报用：

   ```
   table_apply(channel='tejia', batch=批次ID,
     rows=[{skuId, promoPrice=建议价, promoStock=5000}],
     skip_prereq_check=True)
   ```

   特价前置池不需要前置闸。

2. `skip_owner_check=True` **仅**在已用商品档交叉过滤本人货后才允许。
3. 报完立刻用 `ms_submit_list(38801203)` 回查任务状态，下载失败明细 xlsx；失败原因若不是「重复报名在跑」，列出原因汇总。
4. 输出汇总表：可报总数 / 归属过滤后 / 规则剔后 / 提交数 / 成功数 / 失败原因分布。

## 四、后续「5.9减5」「4.9减4」券池（只评估，不直接报）

1. 池子：特价-后续（活动 `101857088` / area `42839704`）。先拉「已报名 + 可报价」清单。
2. 在前置池已生效的 SKU 里，按上面两条承担公式重新筛；**两条都 ≥0** 才允许进后续券池；不满足的明列不归入原因。
3. 评估表先只读给结论（单 SKU：建议价 / 采购价 / 快递费 / p1 / p2 / 能否进），确认后再执行报名。

## 注意

- 「建议价」就是特价池给的「报名价上限」，不是自己拍的价。
- 直通脚本里「非本人货」最容易踩坑，必须保留「与本人商品档取交」步骤，不要信规划器默认范围。

## 完成留痕

```powershell
python scripts/jx_task.py done --task tejia_weekly `
  --summary "可报120/归属过滤后18/规则剔后14/提交14/成功13/失败1（重复报名在跑）" `
  --metric 可报总数=120 --metric 归属过滤后=18 --metric 规则剔后=14 --metric 提交数=14 --metric 成功数=13 --metric 失败数=1 `
  --evidence 回查=ms_submit_list(38801203) 失败明细xlsx
```

「提交成功」即可记 `done`（前提：清单已由采销本人确认）；提交失败、重复占坑、价格被驳回均为 `fail`，
并写平台原始原因。回查结果建议写进 summary，不作为完成门槛。
