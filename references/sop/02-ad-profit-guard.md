# 02 广告入池与出池监控

- task_id：`ad_profit_guard`
- 优先级：P0
- 执行人：李四
- 排期：每天 09:00，数据日期为执行日前一自然日（单日、离线 T-1）
- 依赖：`blacklight`（黄金眼 / EasyBI / 京准通）、JoySpace、京ME

## 目标

查询「你的采销组」各采销名下京喜自营商品，对**投前履约毛利率 < 0 且昨日实际在投**的商品逐项停投，并留下可审计的表格、群消息和回读结果。

## 执行步骤

1. 用本人有效登录态和业务权限查询；不借号、不编造缺失数据。
2. 筛选条件：
   - 投前履约毛利率 < 0；
   - 数据日期严格为前一自然日；
   - 前一日广告曝光 > 0 且广告消耗 > 0（视为实际在投）。
3. 明细至少包含：
   - 数据日期、广告报表 PIN、实际可操作京准通账号、采销姓名、采销 ERP；
   - SPU、商品名称、投前履约毛利率、投后履约毛利额；
   - 广告 ROI、昨日曝光、昨日广告消耗、计划 ID。
4. 逐项停投：
   - 先通过京准通全站营销计划核对广告 PIN、实际账号、计划与商品映射；
   - 执行平台要求的 dry-run/预演，取得并使用确认令牌后再正式停投；
   - 操作后逐项回读平台状态；
   - 已经暂停的标记「操作前已暂停」，不重复停投；
   - 新停投标记「本次停投成功」；
   - 失败项保留平台原始失败原因；
   - 不得把接口受理等同于已生效，以状态回读为准。
5. 每日新建一份 JoySpace ET 在线表格，标题包含数据日期：

   `你的采销组负毛利广告商品停投明细_YYYY-MM-DD`

   写入全部明细、停投结果、回读状态和回读时间。SPU、计划 ID、PIN、ERP 必须按文本写入，禁止科学计数法或截断。

6. 将表格共享给京ME群「你的作业同步群」（群号 `<你的京ME群号>`），设置为该群成员可编辑；不得开放到超出目标群。写入后回读验收表头、行数、SPU 完整值、编辑权限。
7. 向群 `<你的京ME群号>` 发一次汇总消息：数据日期、筛出数量、本次新停数量、操作前已暂停数量、失败数量、在线表格链接。消息中 @ 当日停投商品涉及的全部采销 ERP；先核实其在群内，去重后 @；无符合商品时不 @ 人。
8. 当日无符合商品：仍创建只有表头的表格，并在群内发「昨日无符合停投条件商品」。
9. 幂等检查：同一数据日期若已有完整成功记录、在线表格和群消息回执，不重复停投、不重复建表、不重复发群消息；结果未知时先回读，不盲目重试写操作。
10. 保存并报告执行回执：数据日期、查询完整性、表格链接、权限回读、各商品停投回读、群消息回执。部分失败也要生成表格并明确汇总失败项，不隐藏。

## 完成留痕

```powershell
python scripts/jx_task.py done --task ad_profit_guard `
  --summary "T-1 筛出3/新停2/已暂停1/失败0；表格与群消息已回读" `
  --metric 筛出数=3 --metric 本次新停数=2 --metric 操作前已暂停数=1 --metric 失败数=0 `
  --url "<JoySpace 表格链接>" `
  --evidence 权限回读=群成员可编辑 --evidence 停投回读=3/3已暂停
```

失败项不隐藏；只要存在失败，`summary` 必须写失败数和待人工项。
