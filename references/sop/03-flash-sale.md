# 03 秒杀提报

- task_id：`flash_sale`
- 优先级：P0
- 执行人：全员（各自用本人 ERP，只处理本人名下 SKU）
- 排期：每天，覆盖 T+3～T+5 三场
- 依赖：`blacklight`（yx 营销报名）

## 固定参数

换活动只改参数块，不改流程：

| 参数 | 值 |
|---|---|
| **资源位 ID（resourceId）** | **2858**（秒杀） |
| **收品池 areaId** | **313601**（接口里传这个，不是 2858） |
| **活动编号 activityId** | **101666814**（当前场次；每天与提报链接核对一次） |
| 场域 | **京喜自营**（`applySkuType=3`） |
| 活动 ID | 从当天 yx 提报链接读取，禁止跨天复用 |
| 单次报名 | 按平台表单 |
| 场次 | 20:00 场（`session_value=20:00:00`、`expected_time=20:00:00`） |
| 时间 | T+3～T+5，每天一场 |
| 时长 | 24 小时（`activityDuration=24`，定价与提交必须同口径；有 48/52 选最长时两边一起改） |
| 秒杀打标 | 否 |
| 提报价 | 可报名商品表 E 列 |
| 促销数量 | 5000 |

> 2026-11-20 本机实跑实证：`getBatchId(313601,'2026-11-24 20:00:00')=7284423`；`2858` 当 areaId 会返回「开放收品池未发布」。回读按 **SKU + batchId** 比对（同 SKU 可能同时存在旧批次记录，只按 SKU 匹配会误判）。

## 执行步骤

1. **获取可报名单**：打开 yx 提报链接，按参数填表单，保存并下一步，下载可报名商品表；记下每天对应 `batchId`，E 列即提报价格。
2. **清洗**（按顺序，命中即剔除）：
   1. 东东农场标题 → 永不提报，优先删。
   2. 毛利率 < 0 → 公式 `(平台试算客户到手价 − 采销可控价) ÷ 平台试算客户到手价`，价格取 OSW + 券后价接口。
   3. 广告在池 < 15% → SPU 维度、T-1～T-3、GE 看板投后毛利率。
   4. 互斥促销（便宜包邮 / 超级补贴 / 企业价等）。
   5. 主力券冲突（券门槛 > 秒杀价且奖励 ≥1 元）。
3. **红线**：不改标题/京东价/券促/上下架，不自动退活动，剔除只发生在清单层。
4. **三天各提报一场**：用当天清单 + 存活 SKU 生成上传表提交；遇「任务处理中」等 90～120 秒重试（未写入，安全）。
5. **提交成功即 done**：提交回执要留；随后（建议）等约 110 秒按 SKU + 日期回读，核对 `batchId`、场次时间、价格、账号。回读未取到如实写「回读未取到」，不得编造。

## API 链路（给 Agent）

```
dryrun 拿 token
→ table_apply 提交
→ sleep 110
→ applied_by_skus 比对 batchId / 场次 / 价格 / 账号
```

两个已知坑：

- Excel 类型比较：SKU 按文本处理，避免数值/科学计数法。
- `batchId` 不可跨天复用；换活动必须重新查。

## 完成留痕

```powershell
python scripts/jx_task.py done --task flash_sale `
  --summary "T+3/T+4/T+5 三场提交21，回读19，失败2（券冲突）" `
  --metric 可报名单=40 --metric 清洗后存活=21 --metric 提交数=21 --metric 回读成功数=19 --metric 失败数=2 `
  --evidence 回读=applied_by_skus 按SKU+日期比对 batchId/场次/价格/账号
```

提交失败为 `fail` 并写平台原始原因；提交成功即记 `done`，回读未通过只作为风险提示写入 summary。
