# 能力边界：这套工具能做什么、不能做什么

> 用途：对内对外都说清楚，避免「工具应该能自动做」的误判。
> 结论先说：**它是「作业台 + 留痕 + 看板」，不是「无人值守的机器人」。**

## 一、三层结构，各管一段

| 层 | 由谁执行 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 执行层（会话里） | Agent + 本人登录态 + blacklight 等依赖技能 | 按 SOP 取数、预演、提交、回读 | 无人值守自动提交、跨账号、越过权限 |
| 留痕层（CLI） | `scripts/jx_task.py` | 生成执行单、记录 done/fail/skip、落指标与证据、上报 | 判断业务对错、代替提交或回读、编造缺失数据 |
| 汇总层（看板） | 本地 Node 服务 / 已发布静态页 | 展示完成矩阵、完成率、失败、逾期、14 天趋势 | 反向触发执行、修正业务数据 |

一句话：**确定性的事交给脚本，需要登录态和判断的事必须有人在场。**

## 二、确定能做到（已验证）

1. **一个入口管 5 项每日作业**：`plan` / `today` 按计划时间排出今日作业（默认 09:30 开工），带 SOP 路径、依赖、完成标准、频道页限制规则、留痕模板；4 项按需作业不进默认清单。
2. **执行即留痕**：`done` 要求摘要 + 指标（证据可选），`fail` 强制要求原始错误，`skip` 强制要求原因；空口无法标完成。
3. **离线可用**：记录写在本机 `%USERPROFILE%\.jx-selfop\reports.jsonl`，断网不影响执行，恢复后 `report` 补报。
4. **管理员看完成**：`summary` / `status` / 看板给出当日完成率、失败/阻塞数、逾期数、14 天趋势、CSV 导出与回导。
5. **只读快照可外发**：`dashboard/export-static.js --entry simple` 导出矩阵版首页、`--entry full` 导出完整版；已发布到想象力平台 `https://<你的应用名>.joyapp.jd.com`（`/` 矩阵版、`/full.html` 完整版、`/demo.html` 演示，版本更新即刷新，域名不变）。
6. **每日自动执行（有限）**：Windows 计划任务每天 **09:30** 跑 `automation/daily-run.ps1`（可改），生成当日执行单 + 日志；可选顺带起本地看板。

## 三、明确做不到（不要承诺）

### 1. 不会替人做平台写操作

`tasks.json` 里的 `auto: true` 只表示**「有对应的 blacklight / OSW 能力可以做」**，不表示「可以无人值守跑」。
实际提交仍要 Agent 在会话里用本人登录态调用 MCP，且必须先 dry-run、先给确认清单；提交成功即 `done`，回读结果建议记录。
计划任务即使跑起来，也只产出清单与提醒；**没有任何一条路径能让 cron 自己完成报名/停投/打卡/申诉**。

### 2. 08 / 09 / 10 / 11 四项是按需作业，不是每日作业

`cheap_free_shipping`（便宜包邮）、`official_discount_mark`（官方直降打标）、`aftersale_recovery`（售后回收）、
`newcomer_price`（新人价）在 PDF 里只有作业名称，没有负责人和操作细则，已归档到 `references/sop/_ondemand/`。
它们**不进 `plan` 默认清单、不计完成率**；只有用户明确唤起时才执行，且禁止猜测细节。

### 3. 实时性取决于访问哪个地址

- **线上实时版** `https://<你的应用名>.joyapp.jd.com`：`/` 是实时矩阵页（60 秒刷新），数据存平台共享分库，重部署不丢；成员 CLI 配好 `server` + `ingest_token` 后，`done` / `fail` / `report` 直接写线上。
- **本机实时版**（`serve --port 8090`）：断网或局域网内仍可用；成员 `server` 指向管理员 IP 即可，不需要令牌。
- `/full.html`、`/demo.html` 是导出快照（只读、有时间戳），要实时看 `/`。
- 线上只能上报状态与摘要，不会替人执行作业，也不能替你提交。
- 门户访问白名单需管理员在门户管理端逐个加人；不在白名单的人打开会被 SSA 拦。

### 4. 完成率与逾期是固定口径，不会「智能宽松」

| 项 | 口径 |
|---|---|
| 计入完成 | 只有 `done` 和 `skipped` |
| 不计入完成 | `running` / `failed` / `blocked` / `pending` |
| 逾期 | 当日超过 `schedule.time + grace_minutes` 未完成；历史日期未完成一律逾期；`periodic` 不判逾期 |
| 全员作业 | 按名册人数展开（人数 × 当日全员项），一人没做就是缺口 |

所以「昨天忘了点」不会自动变绿，只能 `report` 补真实记录或 `import` 导回线下记录（会标记来源）。

### 5. 不跨账号、不借登录态、不动敏感业务字段

- 只用本人 ERP 与本人权限；不代查别人商品、不替别人接受协议。
- 不自动修改标题、京东价、券促、上下架状态，不自动退出活动。
- 采集接口只接收作业状态记录，不含 Cookie / Token / 密码；但**注意**：把看板发布到想象力平台时，`joycode-mcp.json` 里的 `JOYCODE_PTKEY` 是明文，属本机凭证，不要外发该文件。

### 6. 没有依赖就只能记「阻塞」，不会造假

| 作业 | 依赖 | 缺依赖时 |
|---|---|---|
| 超级补贴 / 秒杀 / 特价 | `blacklight`（yx / jzt / osw / EasyBI） | 停写，`fail --status blocked` 并写缺什么 |
| AI 工具使用 / 双表打卡 | 浏览器 + JoySpace 登录态（无接口，需人工点表） | 未真实提问/未保存成功即 `fail` |
| 品类新差评删除 | 本机 `京东采销自动化助手_直接提报`（全员已装） | 缺程序或 cookie 过期即 `fail`，附路径/日志 |
| 看板 | Node 18+ | 看板起不来，CLI 与留痕不受影响 |
| CLI | Python 3.11+（仅标准库） | 无法留痕 |

### 7. 多机协作需要一台「常开管理员机」

本地看板方案要求管理员机器固定地址、不休眠、防火墙放通对应端口；多人同时上报靠这一台汇总。
已发布的 joyapp 版没有采集能力，两者不能互相替代。

### 8. 自动化只管「提醒」，不管「结果」

- 机器休眠/关机时计划任务不执行，唤醒后需手动跑一次 `daily-run.ps1` 补生成。
- 任务按「仅交互式」注册：本人不登录桌面（或长期锁屏关机）就不会触发，无域账号免密凭据可用。
- 计划任务跑过 ≠ 作业完成；管理员看的是 `done/skipped` 记录，不是任务有没有触发。
- 想留「今天做不了」的痕迹，只能 `fail --status blocked` 并写原因，不能写 `done`。

## 四、什么时候必须人来决策

出现以下任一情况，停下问人，不要自行选择：

1. SOP 里写「需采销确认」的分支（特价报哪些 SKU / 报名价 / 库存；按需项的频次与公式承担）。
2. 接口返回与预期不符、字段缺失、分页对不齐——只记录「未取到」，不猜数。
3. 需要跨出自己的商品/权限范围，或需要借用他人账号。
4. 平台要求签署协议、确认活动规则、承诺价格。
5. 需要批量改价、批量上下架、退出活动等不可逆的写操作。
6. 名册变化（成员本人装完即入册）或开工时间 / 单项时间 / 限制规则要改（用 `config` 写本机覆盖，不改仓库口径）。
